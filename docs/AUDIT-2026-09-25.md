# BricksSnap audit — September 25–26, 2026

## Scope and outcome

Reviewed generation, the built-in catalog, import/export, validation, connection handling, browser key storage and the onboarding flow. Updated the native registry against Bricks 2.4.1. A 22-element Coming-soon page was imported through the Bricks template library, inserted on the authorized WordPress test homepage and saved. A real generation through the separate ChatGPT/Codex sign-in returned five valid native elements using the account's available `gpt-6-astra` model.

This is a functional/code review, not a certification of every Bricks feature or a forensic audit of the WordPress host.

## Findings repaired

| Area | Change and evidence |
| --- | --- |
| AI providers | OpenAI Responses with JSON output and `store:false`; native Anthropic requests; configurable models and connection checks; Azure/OpenRouter support. Failures, refusals and truncation no longer silently produce built-in content. Provider tests use mocks. |
| ChatGPT account | Official Codex app-server sign-in in a separate local auth home. Loopback/origin/header checks; no public account relay. Fixed the thread sandbox enum to `read-only` and supplied `text_elements` in turn input. Real account generation succeeded. |
| Bricks model | Registry of 182 native element/control names; legacy control migration, alpha colors, gradients and responsive defaults. All 60 catalog templates pass structural checks. |
| References | Repair malformed IDs, parents/cycles and CSS ID references while retaining explicit child order. Reject ambiguous duplicate IDs. |
| Export | Preserve supplied global classes/component metadata; selectable section/content/header/footer; JSON file and paste import with validation. |
| Real rendering | Bricks ignored `_gap` on layout elements, quoted entire font stacks as one family, and rendered imported `%root%` literally. Normalize layout gaps to row/column controls, put font stacks in scoped CSS and resolve shorthand to element selectors before export. The corrected live page uses the intended sans-serif font, spacing and rotated plate motif. |
| Browser/server handling | Escape HTML in the JSON preview, restrict Azure origins, cap request/import sizes, reject cross-origin requests, and require opt-in for server-funded keys and MCP. Browser key obfuscation is correctly described as non-encryption. |
| Onboarding | Separate instructions for API keys, local ChatGPT sign-in and ChatGPT-side MCP; explain import, local/hosted differences and remaining destination configuration. |

## Research used

- [Original Reddit discussion](https://www.reddit.com/r/BricksBuilder/comments/1r0xmsl/free_tool_i_was_tired_of_expensive_templates_so_i/): readers asked how to install/use the app, where to access it and whether it was compatible with newer Bricks versions. Those questions informed the connection/import guide and explicit compatibility limits.
- [Bricks AI Abilities and Skills](https://academy.bricksbuilder.io/builder/features/ai-abilities-and-skills/): Bricks now provides direct AI integration. BricksSnap remains a portable template workspace and links users to the official site-editing integration instead of claiming to implement it.
- [Bricks schema](https://academy.bricksbuilder.io/developer/schema/): basis for native names and controls. The schema's `_gap` non-layout scope also explained the live rendering failure.
- [Bricks custom code](https://academy.bricksbuilder.io/builder/features/custom-code/) and the [imported root-selector discussion](https://forum.bricksbuilder.io/t/no-bug-root-selector-in-customcss-not-working-for-imported-json/38390): imported custom CSS needs stored element selectors. Confirmed against the actual saved page output.
- [Official Codex app-server](https://developers.openai.com/codex/app-server/): managed account login, model discovery and thread/turn protocol. Protocol types generated from the installed CLI were also checked.

## Verification

- Automated suite: 108 tests across catalog generation, validation/export, request/provider behavior, MCP, storage, local account boundaries and Codex protocol regression cases.
- Production build, lint and TypeScript check passed. `npm audit` reported zero known vulnerabilities. The external local Codex executable is excluded from build tracing; the account route's traced file list contained no environment/auth files or local test artifacts.
- WordPress: template JSON accepted by the template library and inserted as editable native elements. Saved homepage checked at desktop width and 390px mobile width. No horizontal overflow at either tested width; no unresolved `%root%` in rendered inline styles.
- Local artifacts (ignored by Git): `artifacts/hb-coming-soon/hb-coming-soon.json`, `live-desktop.png`, `live-mobile.png`, and the synthetic generation result `chatgpt-test.json`. Recreate the template with `node scripts/create-hb-coming-soon.mjs`.
- Local ChatGPT: account status and actual HTTP generation succeeded. The browser's first request timed out; a subsequent minimal generation completed successfully in the UI. The first browser timeout's cause was not established. Screenshot: `artifacts/hb-coming-soon/chatgpt-ui-success.png`. No real API-provider generation was performed with user API keys.

## Remaining limits

- Schema/structure checks do not validate every nested setting, add-on element or destination dependency. Only the Coming-soon page received this full live rendering check; the complete catalog was tested structurally.
- JSON-file import is the verified Bricks path. Automated Ctrl+V did not insert the template in the tested browser session, so clipboard import is not claimed as verified.
- Custom breakpoints, fonts, images, menus, query data, forms, login/social integrations, placeholder links and component dependencies require destination review. Built-in forms do not invent recipients or working integrations.
- Local ChatGPT sign-in supports text prompts and consumes Codex account limits. It is not a general OAuth connection for a public multi-user Vercel service. MCP connection inside ChatGPT has not been exercised end to end.
- The earlier WordPress compromise has not been forensically investigated or certified resolved. Publishing this test page does not establish that the host is clean.
- No deployment or release of this final documentation/test patch was performed. Existing user commits remain intact.
